# Mobius differential testing

This repository has two differential harnesses that reuse the same production-side catalogs and never
run as part of the fast PR gate:

1. **Formula harness** (`tools/Fineage.MobiusDiff/scenarios`, `oracle`, `java/MobiusFormulaDriver.java`) —
   pure combat/stat formulas against a Mobius CT0 reference tree.
2. **Behavioural AI reference set** (`tools/Fineage.MobiusDiff/scenes/ai`, `oracle/ai`) — deterministic
   scenes that drive the production `ZoneWorld` and compare normalized observations with an independent,
   source-backed AI rule model.

## Behavioural AI scene format

Every file in `scenes/ai/*.json` is one executable scenario. The same file drives both sides:

- `player` / `extraPlayers` — starting position, level, karma and HP (additional players exercise hate
  transfer between two targets).
- `npcs[]` — stable scene role, **Mobius id** (`mobiusId`), **Fineage id** (`fineageId`), source path,
  spawn position, HP percentage, respawn delay, initial `_globalAggro`, and optional leader role.
- `actions[]` — ticked world actions: `move`, `damage`, `karma`, `setGlobalAggro`.
- `observe.ticks` / `observe.fields` — normalized per-step values: aggro target, per-player hate,
  chase/return, social/clan helper target, leader/minion count, raid skill set, death/corpse/respawn,
  active think state and world NPC count.
- `oracle` — committed golden trace path and reference-tree label.
- `tolerances` / `knownDivergences` — comparison tolerances and report-only notes. A note never changes
  PASS/FAIL.

`scenes/ai/manifest.json` is strict. `--ai-all` refuses to run unless every required category reaches
its minimum scene count, every listed scene exists exactly once, and the total is 30–50. A partial or
renamed catalog is a hard failure, not a smaller successful run.

## Production side

`AiSceneProbe` constructs a normal `ZoneWorld` with a fixed clock, fixed random streams, a custom spawn
map and real `ZoneSession` characters. It calls the production entry, fixed-step simulation, combat,
aggro, minion and respawn paths. It does not contain NPC-specific branches and does not modify AI rules.
The only production seam added for the harness is an internal spawned-NPC count diagnostic.

## Oracle boundary — model, not full runtime

`MobiusAiReferenceModel` is an independent model of the cited CT0 rules over the Mobius-extracted
catalogs (`data/npcs.json`, `data/npc-minions.json`). It is **not** a headless Mobius GameServer run.

- `fullServerVerified` is always **false**.
- `fineageOutputUsed` is always **false**; expected traces are never generated by copying Fineage output.
- The committed blocker records that the Mobius CT0 source is available at
  `../../Fineage-Backend/ref/mobius-ct0-interlude`, but a full headless GameServer/MySQL runtime is not
  wired in this checkout.

Therefore this harness proves a Fineage-to-reference-trace differential boundary. It does **not** claim
Mobius full-server parity, and it must not be used to upgrade a parity matrix row to “verified by Mobius
runtime”. That upgrade requires a real headless CT0 run.

## Run

```bash
# all scenes, real PASS/FAIL exit code; reports under local-logs/ai-reference-diff/
dotnet run --project tools/Fineage.MobiusDiff --configuration Release -- --ai-all

# one scene
dotnet run --project tools/Fineage.MobiusDiff --configuration Release -- \
  --ai-scene tools/Fineage.MobiusDiff/scenes/ai/aggro-basic-skeleton.json

# regenerate independent goldens (model, not Fineage, not a server)
dotnet run --project tools/Fineage.MobiusDiff --configuration Release -- --ai-all --refresh-ai-oracle
```

Reports contain scenario, category, seed, per-tick parameter, expected, actual, result, oracle provenance
and a reproduction list (player/NPC positions, source ids and ticked actions).

## Known real divergences kept red

The latest local run is 38/43 passing. These five scenes must remain red until the AI behaviour is fixed;
expected values are not bent to Fineage:

| Scene | Evidence |
|---|---|
| `activation-idle-leave-92s` | Mobius region deactivation after 90 s; Fineage trace still reports thinking=true at t480. |
| `activation-returning-stays-awake` | Mobius `returnHome` starts a return walk; Fineage trace reports `returningHome=false` after the target leaves. |
| `return-clears-hate` | Mobius `returnHome` clears the AggroList; Fineage trace leaves hate=1 and `returningHome=false`. |
| `death-aggro-cleared` | Mobius death clears the AggroList; Fineage trace leaves hate=1 on the dead NPC. |
| `hate-clear-on-kill` | Same death AggroList cleanup divergence. |

Reproduce a row with:

```bash
dotnet run --project tools/Fineage.MobiusDiff --configuration Release -- \
  --ai-scene tools/Fineage.MobiusDiff/scenes/ai/activation-idle-leave-92s.json
```

Each of these needs a separate implementation issue; this harness is verification only.

Suggested implementation issue titles/details for the parent to file:

1. **AI: region deactivation must implement Mobius 90-second hysteresis** — scene
   `activation-idle-leave-92s`; observed `thinking=true` at t480 instead of false.
2. **AI: returnHome must clear the AggroList and expose returningHome** — scenes
   `return-clears-hate` and `activation-returning-stays-awake`; observed stale hate=1 and
   `returningHome=false`.
3. **AI: death must clear the AggroList** — scenes `death-aggro-cleared` and `hate-clear-on-kill`;
   observed hate=1 on the dead NPC.

All three are player-visible AI-state differences, not harness or data gaps.

## Nightly CI

`.github/workflows/ai-heavy-nightly.yml` runs on schedule (`02:00 UTC`) and `workflow_dispatch` only. It
builds, executes the full catalog, uploads reports, and runs the Slow tests. There is no
`continue-on-error`, no PR trigger and no fallback that turns a skipped scene into a pass.

Slow tests cover: manifest fail-closed validation, independent-provenance assertions for every golden,
full-catalog execution, preservation of the known red divergences, and a negative-control mutation that
must make the comparator fail.
